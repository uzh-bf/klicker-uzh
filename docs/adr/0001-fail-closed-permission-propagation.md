# Keep permission revocations fail-closed

`Permission`, group membership, entity ownership, and object-hierarchy relations remain the source of truth, while `DerivedPermission` remains the authorization read model. Permission recomputation stays synchronous until measurements show that set-based SQL is insufficient; asynchronous propagation may then be used for grants only after durable dispatch, persistent failure reporting, reconciliation, and a database fence shared by mutations and workers prevent stale writes. Revokes and downgrades remain synchronous and fail-closed.

## Proposed async contract

Gate A showed that the set-based synchronous path still misses the approved latency SLO, so Slice 4 proposes one database-global PostgreSQL transaction-level advisory lock acquired first by every permission source mutation, synchronous revoke or downgrade, and propagation worker. Each source transaction atomically upserts a canonical work key—object type and ID plus recompute mode and optional user scope—and increments its generation; at-least-once workers full-rederive current source state and mark the latest generation processed in the same fenced transaction. Hatchet acceptance advances the dispatched generation only after enqueue, a one-minute reconciliation cadence redelivers unresolved generations, and a persistent database failure record stores a sanitized failure code while leaving work unresolved. The maximum grant-convergence SLO is five minutes from `dirtyAt`, with alerting when `recoverBy` is breached.

The global fence is deliberately conservative: it handles overlapping course, activity, element, answer-collection, group, and ownership roots without a fallible lock-order map, but introduces head-of-line blocking between unrelated permission changes. Hatchet concurrency controls and root-scoped locks were rejected as the initial correctness fence because they do not cover synchronous mutations or roots that converge on the same `DerivedPermission` rows. This proposed extension remains approval-gated after its database prototype; no production schema or call-site conversion is authorized yet.
