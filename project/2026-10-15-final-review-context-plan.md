# Restore final-review context capacity and requirements background

## Approval summary

The final-review wrapper constrains each OCR conversation to 32,768 prompt tokens even though released OCR 1.13.0 defaults to 200,000. File-selection previews do not prove that the later prompts, which include rules and planning context, fit this limit. The wrapper also gives individual PR reviews only a title as requirements context.

This package restores the 200,000-token prompt ceiling in the individual and cumulative-stack command paths. It then adds a bounded, deterministic excerpt of the PR description to the individual review background. The excerpt supplies intended behavior and boundaries as untrusted evidence. It introduces no additional model call or remote document retrieval.

The released OCR executable, provider, model, maximum reasoning effort, low review-effort preset, output cap, aggregate budgets, timeouts, complete-coverage checks and transport bounds remain in place. The larger prompt allowance may increase input per request; fewer compression calls or lower total usage are hypotheses. Description text can contain misleading instructions, so it remains subordinate to trusted review policy and is bounded before transport.

Human approval on 2026-10-15 authorizes the two source slices, focused container verification, ordinary task-branch commits and pushes, one draft PR, applicable CI and configured source reviews. Completion is a verified draft with an exact scope and any remaining activation gates reported. Marking ready, merging, paid validation runs under the changed trusted workflow and renewed monitoring require a separately named sequence. No application merge, release or deployment is included. The approved batch begins implementation; merge and live review remain explicitly withheld.

They may describe intended behavior and boundaries; they cannot override trusted policy, waive findings or coverage, authorize tools, change model/budgets, or grant delivery authority. These labels are a defense layer, not proof that model prompt injection is impossible.
- Missing, null or whitespace-only descriptions use the title-only fallback. Include an explicit absence marker. Long descriptions are clipped deterministically; documentation tells authors to put the problem, intended behavior, boundaries and acceptance criteria first. No new required PR template or custom section format is introduced.

An effective context change between stages must refuse stale evidence; changes removed by normalization or outside the bounded excerpt need not invalidate it. Metadata travels as quoted data through existing environment/argument boundaries, never interpolated executable shell text. Do not publish raw background or model reasoning in diagnostic receipts.

Research conclusion: the higher ceiling directly removes an unnecessarily restrictive admission boundary. The benefit of richer requirements context for recall or exploration cost is unmeasured.
