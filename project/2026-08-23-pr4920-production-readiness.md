Date: 2026-08-23 · Audit: `$rs-production-readiness` · Scope: [uzh-bf/klicker-uzh#4920](https://github.com/uzh-bf/klicker-uzh/pull/4920), head `5c1e0b2fcd`, base `v3`

## Verdict

**not-ready** — Merging unfixed would expose upcoming quiz questions *and their answer keys* to anyone holding an embed link (confirmed by live reproduction against the post-merge stack), and would render the running block twice in the lecturer's live-quiz evaluation (mechanism proven, matching the human reproduction recorded in the PR's own review doc). Both are core-flow breaks introduced by this diff. Fixing both requires server-side changes in `getLiveQuizEvaluation` (restore status-aware shaping; dedupe the active block) plus small frontend repairs. The feature idea itself is sound and worth landing once these are fixed.

## Not checked

- **UX browser pass (dimension worker lost to tool-permission denial):** visual quality was not judged against `$web-design-guidelines`/`$impeccable`; duplicate-block rendering, status-dot tooltips, and the scheduled-element overlay layout (bundled review doc's minor #7: notification renders *next to* content instead of replacing it) were not observed live. Fine-grained UI minors from the bundled review doc (text-xs readability, raw GraphQL enum shown for element type, duplicated i18n keys, `expiresAt` labeled "executed at") remain unverified claims from that document.
- **Deploy & rollback sweep (worker lost to tool-permission denial):** orchestrator verified the load-bearing pieces directly (`displayName` non-null in all Prisma quiz models → schema tightening safe; resolver auth shape; clean auto-merge; committed generated artifacts mutually consistent per GraphQL worker diffs), but a full old-image/new-image rolling-deploy matrix and Helm rollback drill were not performed. No DB migrations exist, so the surface is small.
- **Failure-modes sweep (worker lost to tool-permission denial):** its main threads (index-based selection, missing `skipPollAttempt`, leaderboard Redis coupling) were absorbed into the B2/B3 verifications; deeper resilience scenarios (Redis outage during active block, Prisma timeout behavior) were not independently exercised.
- **Data safety:** no Prisma schema/migration changes exist in the PR (verified; the `prisma-data` filenames seen mid-audit came from upstream v3 movement, not this diff). Backup/restore implications trivially unchanged. New disclosure surface (course name, and everything in blocker 1) is counted under blocker 1 rather than duplicated.
- **Production environment realities:** ingress compression/rate limiting outside the repo; actual staging/prod Helm value overrides (chart ships only defaults); Infisical mirror contents; production reachability of `manage.klicker.com`.
- **Standing CI failures:** root-causing the failing cypress/playwright shards and resolving the two `CHANGES_REQUESTED` reviews belong to the normal merge gates, not this audit.
- **Empirical active-block duplication end-to-end:** no seeded fixture had an active block during the window; verdict rests on decisive static analysis plus the recorded human reproduction.
