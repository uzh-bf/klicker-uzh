# Production readiness — PR #5515 (gamification: nearby leaderboard context, private study streaks, achievement receipts)

Scope: `uzh-bf/klicker-uzh` PR [#5515](https://github.com/uzh-bf/klicker-uzh/pull/5515), branch `rs/gamification-achievement-receipts`, head `9a5dcbe4729dedd2952136a377cd6c954ca19fcc`, base `v3`. Audit run 2026-09-08/09 with the orchestrator on Opus 5 and eight read-only `final-reviewer` workers at xhigh effort, plus two wave-two verifiers.

Unit under evaluation: the system as it will exist **after merge**. The branch diff steered where workers looked hardest; findings anywhere in the stack count.

## Verdict

**not-ready.**

Five blockers are confirmed and one is unverifiable from the repository.

Three confirmed blockers are platform facts. The branch does not merge — eight files conflict. Two required checks are not green. And the backend startup wiring cannot be resolved file by file: the PR's `apps/backend-docker/src/index.ts` imports `startRuntimeMigrations`, which `origin/v3` does not export, so taking `v3`'s `migration.ts` on its own fails `pnpm run check`; taking the PR's side for every conflicting backend file does compile, but discards `v3`'s advisory lock, its wider transient-error classification and its blocking startup; and the hand-merge that keeps both the data and the hardening is written down nowhere. The earlier claim that no resolution compiles was too strong and has been corrected here.

The fourth was reproduced live: the study-streak migration bundles an `ALTER TABLE` with two unguarded `CREATE INDEX CONCURRENTLY` statements, so one interruption wedges every subsequent ArgoCD sync to that environment while Prisma's own bookkeeping under-reports what was applied.

The fifth is the resolution trap. Under the coherent take-`origin/v3` resolution across all four conflicting `apps/backend-docker/` files — the only wholesale-`v3` variant that compiles, and the likely choice because `v3` is the hardened side — the merge deletes the only code that initializes study-streak tracking for participations that already exist. No test on either side pins the registry contents, so CI cannot see the drop, and the affected student is shown a permanently frozen "0 days" badge rather than a hidden card.

The unverifiable blocker is whether the PreSync migrate hook covers the assessment backend's database. Settling it requires comparing two Kubernetes Secrets, which this audit is not authorized to read; the exact digest comparison is written out in its row.

One earlier candidate blocker was demoted. The reconciliation-timeout claim asserted permanence; that is refuted — leaving and rejoining the course leaderboard clears a stuck participation, and the 5000 ms timeout is implausible while the new `QuestionResponseDetail` index is valid. Its constituent facts all hold and appear as majors.

Below the blockers sits a substantial band of majors describing a feature that is under-instrumented and under-documented for production: the backend has no error reporting, metrics or tracing at all, so both new fail-open paths are invisible by construction; two of the study streak's four real states cannot be rendered; the receipt backfill is irreversible with no pre-image; there is no runbook for either new failure mode; and there is no configuration-level way to turn any of the three surfaces off short of an image rollback.

The verdict does not turn on the majors. Even with every major waived, the branch cannot merge, cannot be resolved file-by-file without either a build break or a silent feature drop, and cannot pass its required checks.
