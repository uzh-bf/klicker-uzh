# Next 16 Upgrade Plan

## Goal

Upgrade KlickerUZH from Next.js 15.5.x to Next.js 16 as the first major dependency-upgrade slice after the runtime/security baseline PR.

## Non-Goals

- Do not upgrade to TypeScript 6 in this PR.
- Do not migrate from webpack to Turbopack in this PR.
- Do not replace the PWA implementation with Serwist/native service workers in this PR unless the current plugin cannot build.
- Do not upgrade packages published less than 14 days before 2026-06-01 unless the exact version is manually reviewed and pinned.

## Research

### Official Next.js 16 upgrade guide

- Evidence: Next.js 16 upgrade guide, last updated 2026-03-31.
- Decision: use `next@16.2.6` and `eslint-config-next@16.2.6`; both were published 2026-05-07 and pass the 14-day policy.
- Decision: rename real Next entrypoints from `middleware` to `proxy`.
- Decision: replace `next lint` scripts with direct ESLint CLI scripts.
- Decision: opt out of Turbopack with webpack flags for this PR because the repo has custom webpack config and the PWA plugin uses Workbox webpack plugins.
- Decision: add explicit image config for `qualities`; remove deprecated `images.domains` after confirming equivalent `remotePatterns`.
- Risk: App Router async request APIs, metadata image params, and sitemap params are breaking in Next 16. Local scan must prove whether the repo has affected files.
- Source: https://nextjs.org/docs/app/guides/upgrading/version-16

### Compatibility notes

- `next@16.2.6` requires Node >=20.9.0 and peers React/React DOM ^18.2.0 or ^19.0.0. The baseline branch pins Node 24.16.0, so runtime is compatible.
- `next-intl@4.12.0` peers `next` through `^16.0.0` and React through `^19.0.0`; it is the correct policy-compliant bridge.
- `@ducanh2912/next-pwa@10.2.9` peers `next >=14.0.0` and `webpack >=5.9.0`, but its docs/package notes remain webpack/Workbox-oriented. Use webpack fallback in this PR and leave Turbopack/PWA modernization as follow-up.
- `react-email@3.0.7` pulled `next@15.1.2` transitively. `react-email@5.2.11` and `@react-email/components@1.0.12` are policy-compliant and remove the embedded Next dependency without taking the React Email 6 import migration.
