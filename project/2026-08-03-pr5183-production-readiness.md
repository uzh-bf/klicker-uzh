Scope: branch `claude/klicker-auto-migrations-90b73c` @ `afe477e83` into `v3`, evaluated as the post-merge system. Method: 8 read-only dimension reviewers + 1 verifier per deduplicated blocker (Opus, xhigh). Working material in `project/_local/reviews/` (brief + wave outputs).

## Verdict

**not-ready** (as of `afe477e83`). One confirmed blocker: after merge, the prd overlay renders the PreSync hook with migrator image tag `v3.4.0-alpha.62` — an image that has never been built and that no workflow can produce retroactively (prd builds trigger only on new `v*.*.*` tags, and a re-run of the original tag's workflow uses the tag-era workflow file, which has no migrator jobs). With `migrator.enabled: true` in base values and no prd override, **every prd sync between merge and the next fully-promoted release fails its PreSync hook after a 10-minute ImagePullBackOff — including config-only promotions (e.g. chat-only rolls are normal: chat is on alpha.64 while backend sits on alpha.62) and, critically, emergency rollbacks to any pre-merge tag.** Stg is unaffected (the merge itself builds `…-migrator-arm:v3`, exactly what stg renders). The fix is small (see blocker row), which is why nothing else in this report blocks: two scarier claims were chased and refuted, and the remaining majors are recoverability/observability hardening plus doc gaps.
