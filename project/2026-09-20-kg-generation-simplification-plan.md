# Simplify knowledge-graph generation configuration

## Approval summary

Make domain selection, generation language and question focus predictable without maintaining a second domain registry or manually copying a catalog hash into each environment. Recommend one generator-owned catalog of versioned presets, exposed to Klicker through a small read-only capability contract. Klicker renders supported choices and category previews, freezes the selected policy and language on each build, and dispatches those identifiers. The generator validates and records what it actually used.

First resolve the real delivery boundary. Graph generation currently calls external Hatchet directly; the document-ingestion API is a separate service. The generator's six-domain and question-focus merge requests remain open. An unset staging flag is therefore not the only readiness question. A discovery response must describe the workers that can execute the request, not merely the newest source export.

Preserve Finance/German defaults, existing graphs, pinned retries, authorization, quotas and publication behavior. Carry the actual graph language into question generation. Keep question focus scoped to one batch; retain graph-focus history while proposing removal of that control from new graph requests. Custom taxonomies, additional languages and a General/Mixed default are separate product changes.

Approval mode: **executable batch**, following the user request to work through this plan with a goal on 2026-09-20. Execute source improvements under the addendum below, including focused verification, ordinary task-branch commits/pushes and draft delivery. Merge, new runtime service or credential scope, stack changes, deployment and new paid evaluations remain separate decisions. The user subsequently selected solo execution: main owns implementation, simplification and final self-review; no further subagents are used.

### Primitive impact and binding behavior

| Product primitive                  | Disposition | Owner and contract                                                                                                                                                    | Compositions affected                                                |
| ---------------------------------- | ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| Domain policy                      | Reuse       | Generator owns immutable preset versions and resolved extraction/cleaning semantics. Catalog discovery describes them; it does not create a new policy store.         | Graph extraction, cleaning, previews and retained provenance.        |
| Graph build and publication        | Extend      | Klicker owns authorized selection and source snapshot; generator returns effective policy/recipe evidence. Each build continues to cover all eligible course content. | Queueing, retries, costs, atomic replacement and historical display. |
| Question-generation request        | Extend      | Lecturer chooses one bounded focus and an output language within verified support; Klicker persists them and generator applies them.                                  | Blueprint planning, grounded evidence selection and lecturer review. |
| Knowledge base and source evidence | Reuse       | Existing ownership, ingestion, source identity and publication permissions remain authoritative.                                                                      | Content generation and chatbot retrieval.                            |

**Selection and history.** Keep `(policy ID, version, language)` frozen for each build and retry. Keep old versions executable while queued/running builds reference them, and retain enough metadata to explain historical builds. Selecting a new domain changes the next attempt, not the published graph. A stale or retired selection is shown as unavailable; no automatic version substitution. Legacy all-null requests retain Finance/German omission semantics.

**Catalog and capability.** The read-only contract returns schema version, supported policy ID/version pairs, supported generation languages, localized display labels with a stable fallback, category names/definitions, and a revision or content digest for caching and provenance. It excludes prompts, credentials and source content. Reuse the existing exported schema where possible. Separate descriptive policy history from availability for new jobs. Availability must be tied to the configured workflow and compatible execution fleet; it cannot be inferred from an arbitrary worker's response.

Klicker caches metadata with bounded freshness. Cached data may explain previous selections during an outage; new explicit builds require validated support under the agreed release contract. If no usable capability evidence exists, display a recoverable unavailable state before reserving funds. The legacy route remains available only under its existing integration checks. Unknown schema, unknown pairs and unsupported language fail explicitly. Discovery failures never rewrite a request.

Keep validation at the authorized mutation before reservation, and at the provider execution boundary before model calls. Preserve the local worker's persisted-manifest and compensation checks. Replace duplicated catalog membership checks only when provider rejection is proven to occur before spend. Unknown provider acceptance continues to hold the reservation; a timeout is not evidence of zero spend.

**Language.** First fix graph provenance: select and map `domainPolicyLanguage` (`German`/`English`) to the downstream `de`/`en` protocol. Only legacy null values default to German; reject unknown explicit values. Restore the lecturer's persisted choice independently of interface locale. The first package supports German questions from German graphs and English questions from English graphs. Cross-language question generation is a later contract change because today's validator requires equality. A future override must separately verify translation, terminology and citation fidelity. Additional languages require provider support throughout extraction, cleaning and consumers, not just a longer dropdown.

**Focus.** Expose the existing bounded field on question-generation requests. Blank means no focus; nonblank narrows topic selection within authorized sources, never supplies facts or broadens scope. Insufficient evidence must produce an explicit inability to fulfill the focused batch, not an unannounced whole-course fallback. Preserve flashcard rejection until a separate contract supports it. Proposed UX simplification: remove graph focus from new-build controls, while retaining persisted fields, historical display and exact retry semantics for existing focused builds. Do not silently discard a caller-supplied graph focus through a compatibility API. This removal is a proposal for approval, since the user previously allowed retaining it.
