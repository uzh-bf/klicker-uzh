## Execution details

Use a small application-owned HTTP compatibility middleware before the provider route. For the initial launch POST that requests the browser recovery form (no recovered-state field), set Referrer-Policy: origin on that response only. The provider default no-referrer makes native browser form POSTs send Origin: null. Origin-only policy allows exact-origin verification without disclosing URL paths, queries or credentials. Preserve no-referrer on login, errors with recovered state, handoff and unrelated routes. For POST / only, map Sec-Fetch-Site none to same-origin only when Origin exactly equals the configured APP_ORIGIN_LTI origin and the recovered-state field is a nonempty string. Preserve original metadata in logging by installing the existing logging middleware first. Reject or pass unchanged every other combination; never infer trust from Host, X-Forwarded-Host, Referer, user agent, or token presence. All existing ltijs cryptographic checks must still run. Do not modify node_modules or vendor the provider.

Opus 5.5 approved the scoped referrer-policy correction after its initial critique. If an explicit exact-origin proof cannot support compatibility, retain rejection and report the required browser evidence. No wildcard origins, null-origin exception, state disabling or production replay is authorized.

Validate configured origin at startup as an HTTP(S) origin without credentials, path, query or fragment. Compare the incoming Origin string exactly; reject duplicates, lists and malformed variants. Add bounded Origin classification to existing failure diagnostics (same-origin, cross-origin, null, missing, invalid), never header values. Record a compatibility-applied boolean and a bounded successful-compatibility event. Its purpose is distinguishing safe eligibility without collecting sensitive inputs.

Existing contracts: ltijs 7.0.7 verifies an independently signed recovery token, expiry and matching stateId, a signed expiring state token, ID-token signature and claims, and one-use nonce. Handoff consumption remains unchanged. Existing browser harness checks cross-browser replay and one-use handoff. Historical plans: project/2026-10-26-ltijs-7-upgrade-plan.md and project/2026-11-04-lti-failure-logging-plan.md.

Research: inspect integrity-verified ltijs 7.0.7 and browser Fetch Metadata/Origin behavior. Use only synthetic source fixtures in review packets and repository text. A synthetic metadata override proves the rejected branch; it does not establish the affected Safari version's native header behavior.
