Date: 2026-08-23 · Scope: uzh-bf/klicker-uzh#5446 head `184bd73b23822acbbfc1fbb938d4b7e7c4e8a850` vs merge-base `ee5712399f` · Audit: `$rs-production-readiness` (8 dimensions + 1 verifier; 12 specialist runs total, cap 16)

## Verdict

**ready-with-conditions.** The async redesign is fundamentally sound where it matters most: the copy is one atomic Prisma transaction (no partial copies), replay idempotency is enforced structurally (copied course PK = jobId), the schema delta is additive and old clients keep working, rolling deploys converge by default workflow loading, and every failure mode eventually terminates without corrupting data. No blocker survived verification. Conditions: (1) add minimal duplication-specific observability (worker probes, server-side stale-job sweeper, one aggregated error channel) — the pipeline's worst-case state is currently invisible to operators; (2) fix the 30-minute stale-normalization falsely declaring still-running jobs FAILED and releasing the source lock; (3) reconcile Redis-missing/RUNNING jobs against Postgres before reporting FAILED so a Redis blip cannot misreport a completed copy; (4) document rollback + an operator runbook for the five new failure modes; (5) strip `notificationEmail` from the persisted job args. Note the PR body is stale — it describes the abandoned timeout-bump design, not the shipped async conversion; CI is green except the SonarCloud quality gate (handoff).
