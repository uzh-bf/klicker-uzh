## Binding constraints and known traps

**Do not re-litigate:** target the complete three-layer public stack at `v3-ai`, achieve current participant feature parity, retain default-off activation, and use the public contract as engine compatibility authority. Engines select neither participant policy nor fallback routes. The browser receives no engine/provider service credentials. Preserve existing capability and denial semantics; no fallback may soften identity or tenant isolation. The bounded Python extension remains independently default-off and cannot replace course tools.

**A textual merge is insufficient.** The shared modules move policy into a second application. Resolve against current target behavior, including account entitlement, credit-policy locking, approved custom modes, reasoning visibility, prompts and source normalization. Review every relocated implementation and every Next compatibility export.

**Framework imports can follow the extraction.** Target `apps/chat/src/services/accountUsage.ts:8–31` includes a `NextResponse` adapter. Leave that response adapter in the existing Next module and share the neutral policy; do not import Next into the standalone API. Likewise, keep server-only dependencies out of browser bundles.

**Prompt assets can compile and still be missing at runtime.** Target `promptTemplates.ts:13–29` adds meeting-clock and writing-coach contexts. Preserve the corresponding templates at `apps/chat-api/src/host/prompts/meeting-clock.hbs` and `mode-writing-coach.hbs`, and prove both built applications load them.

**A stopped display turn is not model replay history.** Keep the saved partial answer and stopped marker. Normalize incomplete tool pairs at the host boundary and defend engine conversion. Never invent a successful result or resend unfinished tool execution.

**Cached stack commands may differ from the installed CLI.** Use live help. `rebase` has no documented `--base` flag in the inspected installation. `link` can push branch arguments and create missing PRs; it is not a metadata-only operation. `sync` combines fetch, rebase and publication. Use local adoption/rebase and local checks first, explicit publication second, then link only the three verified existing PR numbers. Hosted candidate CI follows publication. Never use `--prune`, raw force pushes, unstack/recreate, or a lower-layer merge as a shortcut.

**Publication may update only part of the stack.** Read back all three remote heads after every push attempt, including failures. Record accepted and rejected refs. Hold the entire stack on partial publication, preserve checkpoints, and reconcile the actual remote changes before retrying. Never refresh a lease blindly, retry into someone else's changes, or restore a remote ref automatically.
