# KlickerUZH PowerPoint Add-in

This Office content add-in embeds a live-quiz evaluation from KlickerUZH in a
PowerPoint slide. It is a small browser application built with TypeScript and
Rollup; it does not use React or a server-side runtime.

## Supported links

The add-in accepts HTTPS links generated by KlickerUZH for quiz evaluations:

```text
https://manage.klicker.uzh.ch/quizzes/<uuid>/evaluation?hmac=<64 hex characters>
https://manage.klicker.uzh.ch/{en|de}/quizzes/<uuid>/evaluation?hmac=<64 hex characters>
```

The legacy `/sessions/` route remains accepted. Additional KlickerUZH query
parameters such as `questionIx`, `leaderboard`, and `hideControls` are preserved.
Other hosts, paths, identifiers, and HMAC formats are rejected before an iframe
is created.

Each content-add-in instance stores its URL in
`Office.context.document.settings`. On first load, the add-in also migrates the
old `selectedURL<slideId>` setting used by the previous implementation.

## Development

Use the repository-pinned Node and pnpm versions. From the repository root:

```bash
pnpm install
pnpm --filter @klicker-uzh/office-addin clean:cache
pnpm --filter @klicker-uzh/office-addin dev
```

The development server uses `https://localhost:3020`; `manifest.xml` points to
that address. Sideload this manifest manually in PowerPoint after the server is
ready. The retired Microsoft debug launcher is intentionally not installed.

## Verification

```bash
pnpm --filter @klicker-uzh/office-addin check
pnpm --filter @klicker-uzh/office-addin lint
pnpm --filter @klicker-uzh/office-addin test
pnpm --filter @klicker-uzh/office-addin build:docs
pnpm --filter @klicker-uzh/office-addin verify:docs
pnpm --filter @klicker-uzh/office-addin validate
```

`build:docs` creates a production build and replaces the deployed copy at
`apps/docs/static/office-addin`. Production manifest URLs use
`https://www.klicker.uzh.ch/office-addin/`. `verify:docs` proves exact parity
between the runtime files in `dist` and that deployed directory.

Before merge, run the development server and sideload
`apps/office-addin/manifest.xml` in PowerPoint. This manifest points Office at
the local candidate. Verify:

- a URL persists after reopening the presentation;
- separate add-in instances can keep different URLs;
- full-evaluation, question, and leaderboard links render;
- Change URL clears only the current add-in instance.

A browser run with a stubbed Office API can verify the local UI state machine,
but it does not replace this PowerPoint host test.

After deployment, validate the published
`https://www.klicker.uzh.ch/office-addin/manifest.xml` and repeat the PowerPoint
smoke test against production. This is a separate release gate from candidate
verification.

## Key files

- `manifest.xml` — development manifest; production URLs are substituted at build time.
- `src/content/content.ts` — Office settings, migration, and UI state.
- `src/content/evaluation-url.ts` — strict evaluation-link validation.
- `src/styles.css` — local styles shipped with the add-in.
- `rollup.config.js` — build, HTTPS development server, and production asset assembly.
- `scripts/sync-docs.mjs` — deploy and exact-parity check.

The manifest validator is development-only and processes the reviewed local
manifest. Its current Microsoft package retains a transitive `adm-zip` advisory;
do not use it on untrusted manifest or archive input.
